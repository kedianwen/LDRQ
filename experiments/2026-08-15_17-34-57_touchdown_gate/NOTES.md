# touchdown_gate 简述

**要解决的问题**：前四轮训练（first_train / reward_fix / symmetry v1 / symmetry v2）机器人始终没有真正的双腿步态。用 `scripts/diagnose_gait.py` 定量测量后定位到根因：`mdp.feet_air_time_positive_biped` 在"一脚常驻地面、一脚常驻空中"时奖励被顶满（`single_stance` 恒成立、两脚 `in_mode_time` 无限增长、`min()` 被 clamp 在 threshold），**"金鸡独立永不迈步"正好是该项的全局最优解**。实测 v2 与无对称惩罚的对照组腾空占比都是 ~0.06/0.95，证明前三轮的对称性惩罚全在打症状。

**相对上一版（reward_fix_symmetry_v2）的改动**（方案 4.1+4.2，见 `~/kdw/experiment_record/Week03_单腿支撑漏洞根因与步态相位方案.md`）：
- **删除** `feet_air_time`（`feet_air_time_positive_biped`，根因）和 `feet_air_time_symmetry`（已证明无效）
- **新增** `feet_swing_touchdown`（权重 10.0）：只在脚落地那一帧结算，按刚结束的摆动时长给分；摆动 <0.15s 不给分（堵住"快速点地"），>0.45s 不加分（堵住"吊着腿不放"）。权重大是因为信号稀疏——每步态周期只发 2 帧而不是全部 40 帧，折算平均每步约 0.08
- **新增** `feet_air_time_excess`（权重 -1.0）：脚腾空超过 0.6s 后逐帧惩罚超出量，正常摆动 0.3s 完全不触发
- 其余权重全部不变

> 注：方案文档里 4.1 原本写的是 `clamp(last_air, max=threshold)`，实现时发现那样按落地次数累计给分，点地越勤总分越高，会把"快速点地"漏洞放回来，因此加了 `min_swing_time=0.15` 的下限门槛。

**关键参数组**：`num_envs=4096`, `dt=0.002`, `max_iterations=1500`；`feet_swing_touchdown`(w=10.0, min_swing=0.15, threshold=0.45)、`feet_air_time_excess`(w=-1.0, max_air=0.6)。

**训练方式**：先短训 300 轮（run `2026-08-15_17-19-30_touchdown_gate`）→ 诊断确认漏洞已消失 → 用 `train_r1.py --resume` 续训到 1500（即本 run）。**注意本 run 文件夹只含 300→1499 段**，前 300 轮在原文件夹里。

**结果：达标，项目第一次出现真正的双腿交替步态。**

| 指标 | v2（坏的） | 本轮 300 轮 | 本轮 1500 轮 | 目标 |
|---|---|---|---|---|
| 左脚腾空占比 | 0.056 | 0.137 | **0.551** | 0.3~0.55 |
| 右脚腾空占比 | **0.949** | 0.069 | **0.440** | 0.3~0.55 |
| 左右摆动次数比 | 0.806 | 0.663 | **1.044** | ≈1.0 |
| 左右相位差（周期） | 0.502（假象） | 0.043（同相） | **0.500** | 0.5 |
| 左右主频 | — | 0.22/0.09 Hz | **1.34/1.34 Hz** | 相同 |

- 相位差 0.500 这次是**可信的**：两脚腾空占比都在健康区间，不存在"一脚常驻地、一脚常驻空中导致曲线天然互补"的假象（脚本里对这点有专门提示）。
- 步频 1.34 Hz 与方案 4.3 里按生物力学估算的 1.25 Hz 很接近——策略自己收敛到了合理节奏，**方案 4.3 的相位时钟这轮没有用上，暂时不需要**。
- `feet_air_time_excess` 终值 -0.0000，没有任何腿被长时间吊着。
- `track_lin_vel_xy_exp` 0.969（历轮最高），mean reward 28.63，episode length 998/1000，`base_height_low` 终止 0 次、`bad_orientation` 0.04 次。

**遗留事项**：

1. **双支撑期几乎为零**：两脚腾空占比之和 ≈0.99，一脚落地另一脚就抬起，偏"快步/小跑"边界而不是从容的行走。对 sim2real 来说偏激进，Week04 加域随机化后值得关注；要更保守的步态可以调低 `feet_swing_touchdown` 的 threshold 或加一个双支撑奖励。

2. **`dof_pos_limits` 单调恶化，到训练结束仍未收敛**（查 tensorboard 曲线时发现）：

   | 区间 | dof_pos_limits | base_height_l2 |
   |---|---|---|
   | it300-600 | -0.00029 | -0.00018 |
   | it600-900 | -0.00037 | -0.00014 |
   | it900-1200 | -0.00057 | -0.00019 |
   | it1200-1499 | **-0.00084** | -0.00028 |

   全程恶化约 3 倍且末段仍在继续。原因是该项绝对量级太小（-0.00084 对比 `action_rate_l2` 的 -0.053 只占 1.6%），在总回报里没有话语权，PPO 拿它换了 `track_lin_vel_xy_exp`（已达 0.969）——步子更大更快，关节行程顶到软限位。和上面第 1 点是同一件事的两面。

   换算成物理量约为"平均每步全部腿关节合计超出软限位 0.00084 rad ≈ 0.05°"，**当前不构成问题，不建议为此重训**。但关节顶限位对 sim2real 的危害远大于它在 reward 里的分量（真机是硬限位、冲击、模型失配），**Week04 务必盯这条曲线**；真要处理可把 `dof_pos_limits` 权重从 -1.0 提到 -5.0 量级。

   （`base_height_l2` 也被问到，但它中间有回落、趋势弱得多，基本可忽略。）

**注意**：前 300 轮的 run 文件夹 `2026-08-15_17-19-30_touchdown_gate` 在续训完成后**不明原因消失了**（诊断和 resume 时都还在，训练管线里查过没有任何删除代码）。丢失的是前 300 轮的 checkpoint 和 tensorboard 曲线；配置、最终模型、300→1499 全部曲线都在本文件夹里，不影响结论。
