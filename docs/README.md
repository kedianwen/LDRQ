# docs/

Verification reports and screenshots produced by `../scripts/`, plus evidence
captured on the robot itself. These are results/exit-criteria deliverables, not
build artifacts, so they're tracked in git — re-running the scripts overwrites
them with fresh numbers, which is the point. The robot-side captures cannot be
regenerated by any script here, so they are the only copy: don't delete them.

**Reading order for a newcomer:** `technical_report.md` → `system_architecture.md` →
`stageA_kp_sweep.md` → `dod.md`. Labels such as W01 (a week of the project plan),
stage A–D, PG-1 / FR-Q3 (gate and requirement IDs) and "plan 3.6" are explained in
[*How the project was organised*](../README.md#how-the-project-was-organised) in the
top-level README; `dod.md` lists every gate and requirement with its evidence.
