# week04_dr 简述

**要解决的问题**：Week03 产出了 R1 第一个真正的双腿步态，但它只训练过 0–0.5 m/s 直线，且完全没有域随机化。Week04 的目标是 M1 关口三件事：(1) 纯本体 actor 直接可部署（FR-T4）；(2) 域随机化五项（FR-T5）；(3) **PG-1 达标**——0.5–1.0 m/s 指令下线速度跟踪误差 ≤0.15 m/s。

开工前先用新写的 `scripts/eval_baseline.py` 量了 Week03 策略，把矛盾钉死：0.5 m/s 处误差 0.022，1.0 m/s 处 **0.236（PG-1 FAIL）**，但**全程零摔倒**——瓶颈不是稳定性，是 0.5 m/s 以上从没训过。

**相对上一版（touchdown_gate）的改动**：

- **观测历史堆叠**（FR-T4）：policy 组 `history_length=5`，87 → **435** 维。这是"纯本体 actor 不用蒸馏也能部署"的关键——用记忆替代特权量。critic 不加历史（它本来就直接观测 `base_lin_vel`）。
- **域随机化五项**（FR-T5）：摩擦 0.6–1.2、全身质量 ±10%、电机增益 ×0.85–1.15（三项均 `startup`）、外力推动 ±0.5 m/s（`interval` 10–15s）、**控制延迟 0–1 控制步**。
- **命令范围 + 课程**：`lin_vel_x` (0,0.5)→**(0,1.0)**，新增转向 `ang_vel_z` **±0.5**（侧移仍钉死 0）。新增 `command_range_curriculum`（Isaac Lab 2.1 没有现成的命令范围课程），前 1000 轮线性放宽。
- **critic 新增足底摩擦特权观测**（96 → 98 维）。
- 训练预算 1500 → **3000 轮**；`seed=42` 显式固定（FR-T6）。
- **奖励权重一项未动**——Week03 的奖励设计原样保留。

> **控制延迟没有用 Isaac Lab 的 `DelayedPDActuatorCfg`。** 该方案烟测直接失败：R1 在 1.5s 内摔倒，且把延迟设成 0 后轨迹**逐位相同**，证明是执行器模型而非延迟的问题。原因是它是*显式* PD（力矩在 Python 里算），而显式阻尼稳定条件约 `dt < 2J/d`，R1 踝关节 `d=150`、惯量约 0.01 kg·m² → 限值约 1e-4 s，本环境是 2e-3 s，超一个数量级。失败顺序也吻合：roll 在 0.5s 就崩到 −10.6° 而 pitch 才 1.3°（踝关节先垮）。Week02 那句"1200 刚度靠 dt=0.002 才稳"的余量全部来自 PhysX 隐式求解器。改用 action 层延迟（`DelayedJointPositionAction`），反而更贴合部署——延迟以 20ms 控制步计，正是真机策略回路周期。

**关键参数组**：`num_envs=4096`, `dt=0.002`, `decimation=10`, `seed=42`, `max_iterations=3000`；`history_length=5`；DR 见上；`feet_swing_touchdown`(w=10.0)、`feet_air_time_excess`(w=−1.0) 沿用 Week03。

**训练方式**：先短训 300 轮（run `2026-08-17_17-18-51_week04_dr`）→ 双诊断确认单腿漏洞未复发 → resume 到 3000（即本 run，**只含 300→2999 段**）。全程 2h14m，3.06 s/iter。

## 遗留事项

1. **步态已越过飞行相**。两脚腾空占比之和 = 1.062 **> 1.0**，意味着存在双脚同时离地的瞬间；步频也从 Week03 的 1.34 Hz 升到 1.60 Hz。Week03 遗留事项第 1 条（双支撑期≈0，"偏快步/小跑边界"）本轮**越过了那条界**。对 sim2real 偏激进：真机腾空落地的冲击、触地时刻的不确定性都比行走大得多。要更保守可调低 `feet_swing_touchdown` 的 threshold 或加双支撑奖励——但**这会牺牲已达标的 PG-1**，建议留到 W07 真机首次落地时按实测决定，不要现在盲调。

2. **左右腾空占比不对称**（0.416 vs 0.646），右脚摆动时长是左脚 1.54 倍。注意这**不是** Week03 那个单腿漏洞——摆动次数比 0.957、相位差严格 0.500、一致性 1.00，两脚都在正常交替迈步。但不对称本身对真机不利（偏磨损、偏航），值得 W05 导出前再确认一次。

3. **转向跟踪明显弱于直线**：`track_ang_vel_z_exp` 终值 0.257，该项权重 0.5，即约 51% 上限；而 `track_lin_vel_xy_exp` 0.891 已接近上限。转向是课程后期才开进来的。PG-1 不考核转向，但 W06 真机要用。

4. **课程进度与 resume 的交互（影响复现）**：`command_range_curriculum` 用 `env.common_step_counter` 计步，而该计数器 **resume 时从 0 重启**（env 是新建的，只有 runner 的迭代计数从 checkpoint 恢复）。实测 it1000 时 alpha=0.7025 而非 1.0，命令范围实际在 it1299 才开满。**后果良性，但「300+resume 2701」与「一次跑满 3000」不是同一条课程曲线**——README 的复现命令已改成同样的两段式。要让课程对 resume 免疫，需改成按 `runner.current_learning_iteration` 计步，而 env 侧拿不到该量，得另外传入。
