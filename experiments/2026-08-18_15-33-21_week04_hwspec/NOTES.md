# week04_hwspec 简述

**要解决的问题**：核对 [Unitree 官方 R1 配置](https://github.com/unitreerobotics/unitree_rl_mjlab/blob/main/src/assets/robots/unitree_r1/r1_constants.py) 后发现，Week02 拍的执行器参数**覆盖了 `R1.urdf` 自己声明的硬件力矩规格**（URDF 与官方配置完全一致：hip/knee 60、ankle 50）。实测上一版策略 `2026-08-17_17-38-37_week04_dr`：**踝关节 11.57% 的时间输出超过真机额定值，p99 顶死在仿真上限 150 N·m**——该策略在真机上物理上跑不起来。

同时解决 Week04 遗留的两条步态问题（飞行相、左右腾空不对称）。

**根因**：Week02 的判据是"纯关节 PD、无控制器、静态站立 ≥10 s"，据此推出腿部刚度须超过倒立摆的 `m·g·h ≈ 190 N·m/rad`。但 **RL 策略是主动平衡的**，每个控制步都重设关节目标，不需要姿态被动自持——Unitree 在同一台机器人上用 100/40 正是因为策略在做平衡。错在把"为通过站立测试而选的增益"原样带进了 RL 任务。整条链都是它的下游：刚度 1200 → 隐式求解器在 1/60 s 发散 → `dt=0.002` → 显式执行器不可用 → 力矩上限被抬到 150。

**相对上一版（week04_dr）的改动**：

| 项 | 旧 | 新 | 依据 |
|---|---|---|---|
| legs 刚度/阻尼/力矩 | 1200 / 100 / 150 | **100 / 2 / 60** | URDF + 官方 |
| ankle 刚度/阻尼/力矩 | 1200 / 150 / 150 | **40 / 2 / 50** | URDF + 官方 |
| waist / arms / wrist | 400·20·60 / 80·15·40 | **100·2·60 / 40·2·60 / 20·1·33** | 官方 |
| action scale | 0.5 统一 | **按组 `0.25·τ/k`**（0.15 / 0.3125 / 0.375 / 0.4125） | 官方 |
| 初始姿态 | hip −0.26 / knee 0.52 / ankle −0.26 | **−0.1 / 0.3 / −0.2** | 官方 |
| pelvis 高度 | 0.72 | **0.731**（非官方的 0.76，见下） | 实测 FK |
| sim dt / decimation | 0.002 / 10 | **0.005 / 4** | 软增益后不再需要 |
| 对称性 | 无 | **`RslRlSymmetryCfg` 数据增强** | Mittal 2024 |

> **官方的 pelvis 高度 0.76 不能照搬。**关节角能直接用（hip+knee+ankle=0，脚掌保持水平），但把脚掌放到地面的 pelvis 高度取决于足部碰撞几何，Unitree 的 MJCF 与本项目的 URDF 不同。实测本 URDF 腿部 FK 为 0.6778 m，加 0.053245 m 鞋底偏移 = **0.731**。用 0.76 会让机器人悬空 2.9 cm、每次 reset 往下掉。已同步 `base_height_l2` 目标（0.731）与 `base_height_low` 阈值（0.51）。

**关键参数组**：`num_envs=4096`, `dt=0.005`, `decimation=4`, `seed=42`, `max_iterations=3000`, `history_length=5`；DR 五项与奖励权重全部沿用 week04_dr，**一项未动**。

**训练方式**：单次 3000 轮，1h27m。改回单次（不再 300+resume）顺带消除了 week04_dr 记录的"课程进度与 resume 耦合"复现问题——实测 `Curriculum/command_ranges` 在 it1000 精确为 1.0000。

## 结果：**力矩全部合规，PG-1 达标，两条遗留步态问题同时关闭。**

### 力矩合规性（本轮首要判据，cmd 1.0 m/s，64 envs × 400 步）

| 关节组 | p50 | p95 | p99 | max | 真机额定 | 超限比例 |
|---|---|---|---|---|---|---|
| hip/knee | 6.4 | 24.2 | 29.8 | **32.5** | 60 | **0.00%** |
| ankle | 0.4 | 29.2 | 41.8 | **43.1** | 50 | **0.00%** |
| waist | 4.5 | 8.2 | 8.8 | 9.4 | 60 | **0.00%** |

峰值仅用到额定的 54%（hip/knee）与 86%（ankle），**仍有余量**。对比旧策略踝部 11.57% 超限、p99 顶死 150。

|---|---|---|---|---|
| 0.3 | 0.021 | 0 / 0 | 52.3 | 0.0809 |

**PG-1：PASS**，最差 0.050 m/s（门槛 0.15）。扰动条件（摩擦 0.6 + 每 5s ±0.6 m/s 侧推）下仍 **PASS，最差 0.074，零摔倒**。

### 三版对比

|---|---|---|---|

| 扰动 PG-1 | FAIL 0.377 | PASS 0.100 | **PASS 0.074** |
| 扰动下摔倒 | **553 / 553** | 2 / 192 | **0 / 192** |
| 1.0 m/s 能耗 | 219.9 W | 237.3 W | **137.8 W** |

> 能耗降低 42%，且**动作平滑度的 0.099 → 0.128 不可直接比较**：action scale 从 0.5 缩到 0.15，同样的物理运动对应的动作数值本就大约 3.3 倍。换算成实际弧度是 0.050 → 0.019 rad，实为大幅改善。这个口径问题以后跨 action scale 比较时都要注意。

### 步态：两条遗留问题同时关闭

| 指标 | week04_dr | **本轮** | 目标 |
|---|---|---|---|
| 左 / 右腾空占比 | 0.416 / **0.646** | **0.466 / 0.459** | 0.3–0.55 |
| 腾空占比之和 | **1.062（有飞行相）** | **0.925（双支撑恢复）** | <1.0 |
| 摆动时长比 | 1.537 | **0.976** | ≈1.0 |
| 摆动次数比 | 0.957 | **1.006** | ≈1.0 |
| 主频 | 1.60 / 1.60 Hz | 1.35 / 1.34 Hz | 相同 |
| 相位差 / 一致性 | 0.500 / 1.00 | **0.501 / 1.00** | 0.5 / 1.0 |

不对称与飞行相**同时消失**。两项修改各自的贡献未做消融（对称性增强与力矩上限收紧一起上的），若需归因需补一次单变量实验。训练中 `Mean symmetry loss` 从 0.0020 单调降到 0.0003，说明增强确实在起作用。

### 训练效率

3.06 s/iter → **1.76 s/iter（1.74×）**。dt 单独约省 2.5×，但对称性增强把 PPO 的 minibatch 翻倍吃回一部分——**净收益是 1.74×，不是 2.5×**。

### 意外收获：软增益反而更好学

| run | it300 ep_len | it1000 reward |
|---|---|---|
| week04_dr（旧执行器） | 470.7 | 10.05 |
| **week04_hwspec** | **905.7** | **13.74** |

在多了对称性增强、满量程指令和转向的条件下仍然更快。合理解释是旧配置 `scale 0.5 × stiffness 1200` 让控制器工作在近饱和区（0.05 rad 动作即产生 60 N·m），动作到状态的映射条件极差。

## 遗留事项

1. **转向跟踪仍偏弱**：`track_ang_vel_z_exp` 终值约 0.31（权重 0.5，即约 62% 上限），而直线跟踪 0.928 已接近上限。比 week04_dr 的 0.257 有改善但仍是短板。PG-1 不考核转向，W06 真机要用。建议 W05 前单独补一次转向专项评测（目前 `eval_baseline.py` 只测直线）。

2. **`inspect_r1.py` 的站立检查已不再适用**。真机增益下 R1 无法被动保持站立（实测 1 s 内降到 0.508 m），这是**预期且正确**的——那是错误判据。该脚本作为 Week01/02 的资产核对工具仍有效，但其"站立"部分不能再当作回归测试。需要新的资产级烟测。

3. **两项修改未做消融**：力矩收紧与对称性增强同时上线，无法区分各自对步态对称性的贡献。若组会被问到归因，需补单变量实验。

4. **`docs/joint_check.md` 已过期**：其中的驱动增益表反映的是旧的 1200/100 参数。重跑 `inspect_r1.py` 即可刷新，但注意它会同时覆盖 `docs/r1_standing.png`，而新增益下那张截图会是"摔倒中"的姿态。
