# reward_fix_symmetry_v2 简述

**要解决的问题**：`reward_fix_symmetry`（方案A v1）用瞬时占空比设计的对称性惩罚有公式 bug——单脚支撑的任意瞬间都会被判定为"不对称"，导致策略学会干脆不单脚支撑（两脚并拢同步小跳），没有解决原本的左右脚点地骗奖励问题。v2 改用完整周期指标重新实现，不改变要解决的核心问题（左右脚不对称）。

**相对上一版（reward_fix_symmetry v1）的改动**：`feet_air_time_symmetry_l1`（`tasks/r1_flat/mdp.py`）改用 `last_air_time`（上一次**已完成**摆动相的时长）比较左右脚，取代 v1 用 `current_air_time`/`current_contact_time` 算的瞬时占空比。只在每次摆动真正结束时更新一次，不会在单脚支撑进行中就产生虚高惩罚。权重仍为 -0.3（与 v1 一致，便于对比），其余权重不变。

**关键参数组**：`num_envs=4096`, `dt=0.002`, `max_iterations=1500`；`feet_air_time_symmetry` weight=-0.3（v2 公式）。

**结果：判定失败。（此结论为 2026-08-15 用 `scripts/diagnose_gait.py` 实测后修正，之前误判为"成功"，见下）**

先前基于 tensorboard 指标 + 抽帧目视，我曾把本轮判定为"成功"，这个结论是**错的**。用户复核后仍报告"左脚正常行走、右脚点地"，遂写了 `scripts/diagnose_gait.py` 做定量测量，实测结果（32 envs × 12s）：

| 脚 | 摆动次数 | 平均摆动时长 | **腾空时间占比** |
|---|---|---|---|
| left_ankle_roll_link | 4.5 | 0.140 s | **0.056** |
| right_ankle_roll_link | 3.6 | 3.332 s | **0.949** |

**右脚 94.9% 的时间在空中，左脚 94% 的时间在地上**——这根本不是"右脚点地骗奖励"，而是**整个机器人单腿（左腿）支撑前进，右腿基本一直吊在空中**，右脚偶尔落地一下就是用户看到的"点地"。正常行走时两只脚的腾空占比都应该在 0.4~0.5 左右。

**之前误判的原因**（两个都要记住）：
1. **看错了指标方向**：我把 `feet_air_time` 恢复到 0.191 当成"步态变好"，实际上这个数值高恰恰是漏洞被吃满的结果（见下面根因）——这个指标在这个漏洞下是**越高越糟**，不能当作步态健康度指标用。
2. **抽帧目视不足以判断步态**：单腿吊着的姿势，在静止画面里和"迈步跨出去"几乎一模一样。靠抽几帧图看是分辨不出来的，必须看连续视频或者直接测接触时序。

**真正的根因（此前三轮都没定位到）**：`mdp.feet_air_time_positive_biped` 的公式在"一脚常驻地面、一脚常驻空中"时会被**顶满**：
```python
in_contact   = [左True, 右False]
in_mode_time = [左contact_time(一直涨), 右air_time(一直涨)]
single_stance = (在地脚数==1) = True      # 永远成立
reward = min(左contact_time, 右air_time)  # 两个都很大
reward = clamp(reward, max=threshold)     # 直接顶到 0.4（该项最大值）
```
也就是说**"金鸡独立永远不迈步"正好是这个奖励项的全局最优解**。这个漏洞从 `reward_fix` 把该项权重从 0.25 提到 1.0 起就存在了，我前面三轮（reward_fix / v1 / v2）都在给它打补丁，却没动这个根子上的公式。

**对照组证实与对称性惩罚无关**：对 `reward_fix_1500`（完全没有对称性惩罚项）跑同一诊断，左/右腾空占比 = 0.066 / 0.949，**和 v2 几乎一模一样**。说明这个单腿步态在加对称性惩罚之前就已经存在，v1/v2 两轮改动都没碰到问题本质。
